# 诡秘之主 · GvG 战术板（正式版 v1.0.0）

创作者：小绿叶子，Deepseek-v4.1-Flash

《诡秘之主》GvG 场景的**离线战术板**：在 SVG 沙盘上摆队伍 / 单人标记、画推进路线、按阶段对比、按地图模式推演，并把编成、导入、战后分析串成一条流程。

- 技术栈：HTML + CSS + 原生 JavaScript + SVG，**零依赖、零构建、零联网**。
- 双击 `index.html` 即可通过 `file://` 运行；全部用经典 `<script>` 顺序加载，不用 ES module、不 fetch 数据。
- 五张地图：灰雾试验场（自由沙盘）、猎龙之城（攻城占点）、四方战场（守卫争夺积分）、星墓高原（拉车护航）、霍纳奇斯山脉（七点占点计分）。
- 六个真实职业，固定配色见 [6.9](#69-六职业与配色)。
- 推演引擎、战后分析阈值、地图几何参数中**凡是标注「假设值」的都是可调默认值，不代表官方规则**。

---

## 一、运行方式

1. 双击 `index.html`，或在浏览器打开 `file:///.../index.html`。
2. 推荐 Chrome / Edge 最新版（依赖 Pointer Events、HTML5 Drag & Drop、`localStorage`、`DecompressionStream`）。
3. 不需要 Node、本地服务器或联网。
4. 首次打开自动新建工程：地图为 `灰雾试验场`，含 1 个空方案、1 个「接敌前」阶段、5×5×5×6 空编成骨架。
5. 之后每次改动由 `js/storage.js` 自动写入 `localStorage`（键 `gm.tactical.board.v1`，450ms 防抖）。
6. 从零开始：先「导出 JSON」备份 → 控制台执行 `localStorage.removeItem('gm.tactical.board.v1')` → 刷新。
7. 数据只存本机浏览器；清站点数据会丢。重要布置请用顶栏「导出 JSON」（`Ctrl+S` 同效）。

## 三、界面与操作

### 3.1 顶栏

战役名、地图切换、保存状态、战后分析、导入 JSON、导出 JSON。无「编队」按钮——编队配置入口在左栏。

保存状态文案：`新工程` / `已恢复` / `已自动保存 · HH:MM:SS` / `保存中…` / `本地存储不可用` / `保存失败：…`。

### 3.2 左栏：当前编成（实时）

- 只显示 `project.teams`（live 实时编成），配置窗口的任何改动约 0.4 秒后自动刷新这里；**左栏不再有预设阵列**。
- 结构：联盟列表头 → 团队列表头 → 5 个小队列；每列 6 名成员自上而下，列头写小队名。
- 缩略格：职业色底 + 游戏名小字；名字不超过 3 字时右上角补技能首字。
- 两级折叠：联盟头、团队头可点击折叠 / 展开，折叠后显示人数与职业构成小色条。折叠状态存 `gm.tactical.ui.v1`（纯 UI 状态，不写工程、不进撤销栈）。
- 点击缩略格 = 选中该成员（右栏切属性检查器）。
- **四档拖动粒度**：
  - 拖联盟头 / 团队头 → 沙盘生成整队标记（引用该节点全部成员）；
  - 拖小队列头（`⠿` 抓手）→ `ref.type = "squad"` 小队标记，名称「团队名/小队N」，人数取实际人数；空列禁止拖动并提示「该小队暂无成员」；
  - 拖单个缩略格 → `ref.type = "person"` 单人标记。
  - 小队列头点击不折叠、不载入预设，折叠只由联盟头 / 团队头负责，拖动与点击互不干扰。

### 3.3 编队一体视图（左栏「编队配置」）

铺满视口的三栏覆盖层，一处标题栏 + 关闭按钮 + 导入 / 导出 / 预设操作：

| 栏 | 内容 |
| --- | --- |
| 左 60% | 队伍配置（5×5×5×6 骨架、30 格团队面板、抽屉编辑） |
| 中 `1fr` | 候补池（拖到左侧格子即可上场） |
| 右 20% | 编成总览（只读：规模 KPI、职业占比、技能携带） |

- 固定骨架：联盟 5 槽 × 团队 5 槽 × 小队 5 槽 × 每队 6 格，空槽灰暗但存在；无「＋联盟 / ＋团队 / ＋小队」按钮；联盟 / 团队 / 小队名均可双击改名。
- 点空格直接生成队员（不弹输入框）：行 1 战士、行 2 歌颂、行 3 学徒、行 4 占卜、行 5 窥秘、行 6 观众；默认形态战士坦克、观众治疗、歌颂输出、其余输出；歌颂另有辅助可选；占位名「职业+序号」。
- 点已填色块 → 右侧抽屉：游戏名 / 职业 / 形态 / 四槽（人脉 / 密偶 / 技能 / 备注）。换职业时非法形态自动校正。
- 「确认」= 关闭抽屉（改动已实时生效）；「取消（回滚）」= 撤销抽屉内未确认字段并写一条撤销记录。
- 拖动（真实 HTML5 DragEvent）：
  - 格到格 = 交换（目标为空 = 移动）；跨小队 = 换人；
  - 拖到团队 / 联盟页签 = 跨团队 / 跨联盟移动，自动落到目标下第一个空位并切页签；
  - 拖出面板或拖到「移出队伍」区 = 移出（写一条撤销记录）。
- 批量操作：点「批量操作」进入选择模式（Esc 退出），支持 Shift 连选、空白拖动框选、全选本团队 / 当前小队 / 按职业全选；动作含改职业与形态、移入候补池、移到指定小队、清空技能槽、删除。整批算一次撤销。
- 快捷键见 [九、快捷键](#九快捷键)。

### 3.4 中央沙盘

- `viewBox` 固定 1600×1000，`preserveAspectRatio="xMidYMid meet"`；缩放换算走 `getScreenCTM()` 实测，不写死像素。
- 工具栏：选择 / 抓手、路线 / 集结 / 矩形 / 圆形 / 标注、撤销 / 重做 / 删除 / 清除本层 / 吸附网格、缩放百分比。
- 滚轮缩放（0.4×–8×）、空白拖动平移、`Space` 切换抓手 / 选择；无工具栏「全图」按钮，`board.fitView()` 只在切图 / 导入 / 初始化内部调用。
- 标记可任意放置：墙体只是底图美术层，墙内、地图外沿以内都能落标记；不再有「不可通行墙体」拒放或 toast。旧 `project.wallStrict` 与「严格墙体」开关已删除。
- 保护结界（仅四方战）是底图美术层：4 个圆画在 `layer-base`，不进图层面板对象列表，归属固定为最近出生点所属势力；敌方个人标记落入只描边变红 + 一条提示，无数值结算。
- 标记可拖动改位置；检查器可改朝向（`0~360`，超出按 360 取模）、状态（待命 / 推进 / 交战 / 减员 / 阵亡）、敌我关系（我方 / 友方 / 敌方）、备注、坐标。
- 联盟 / 团队 / 小队 / 个人四级标记统一为**半填充圆**：联盟 / 团队 / 小队的内圈填充色 = 敌我关系（我方绿 / 友方蓝 / 敌方红，alpha 0.4）；个人级内圈改用成员职业色。外圈描边 = 状态，五状态统一实线、同一线宽（普通地图 2.2 px / unit 地图 0.5 u），只换颜色。个人标识框为两行：名称 + 「敌我 · 职业 · 状态」，过长时优先省略职业名、状态不截断。半径按级别与人数分层：联盟随人数 30~50 px（unit 4~8）、团队 15 px（3.2 u）、小队 10 px（2 u）、个人 7 px（0.5 u）。
- 四个级别的敌我关系**完全独立**，各自一个字段，改一级不影响其他级别；新建标记与旧存档缺字段时一律默认**敌方**。
- 标识框左上角有一个引线锚点小圆点；标签因避让偏离默认位置时，引线从锚点连到标识框最近的边，标签回默认位则不画线。
- 标识框显示可分级设置「固定显示 / 仅选中时显示」（图层面板），写入 `project.labels.pinned`。
- 绘图：路线（单击加点，双击 / `Enter` 结束，`Esc` 取消）、集结点、矩形 / 圆形区域、文字标注。
- 图层面板：底图 / 目标 / 区域 / 路线 / 标记（队伍）/ └ 个人标记 / 标注；双层地图（星墓高原）在列表上方多一行「高程」切换（`二层` / `地面层`），进入时**默认二层**，台下镂空层需手动切换，按钮高亮 + 面板标题右侧标签共同标识当前高程。
- 热区（选择工具下）：猎龙之城 9 个、四方战 5 个，悬停高亮、点击触发对应动作；星墓高原只有中央占领圈 1 个可拖动对象（据点 / 广场 / 楼梯为纯背景）；底图地形不可选中。
- 战术级 LOD：unit 图缩放后 `1 unit < 2.4 px` 时隐藏全部标签（命中圆保留）；HUD 显示 `1 unit = ? px · 主通道 N u` 与「此处约 N 人并排」。

### 3.5 右栏（随选中状态切换，图层面板常驻）

- 未选中：标题「地图态势」。地图卡三行（地图 / 模式 / 势力 · 目标）+ 四势力色点，说明与玩法规则收进折叠区。下方按模式显示：
  - 猎龙之城：攻城态势卡（石碑归属、城门 未解锁 / 可攻 / 已破、中央高台 0–100 积分、胜者）；

  - 星墓高原：骑士归属、护送进度、占领圈、已交付次数与返回目标。
- 选中单位（队伍 / 成员 / 标记 / 绘图对象）：切换为「属性检查器」。
- 图层面板固定在右栏底部（`max-height: 46%`，可滚动），不随选中状态消失。

### 3.6 方案与阶段

- 同一地图可存多套方案：新建 / 复制 / 改名 / 删除 / 下拉切换。
- 每方案多阶段，切换即切快照；「＋阶段」复制当前阶段 `markers` / `shapes` 并保留 id，同 id 的坐标差即位移。
- 「差异」叠层显示相对上一阶段：位移（绿线）、新增（绿圈）、消失（红叉），阶段条右侧显示数量。

### 3.7 布局与缩放口径

- 主界面三栏：`minmax(0,25%) minmax(0,1fr) minmax(205px,12%)`，4px 列间隙；≤1180px → `24% / 1fr / minmax(200px,14%)`；≤980px → `22% / 1fr / minmax(190px,15%)`。

- 沙盘窗口 resize 后 120ms 防抖重算 LOD 与 `1 unit = ? px`，不改用户当前缩放。

## 四、地图

### 4.0 四势力名称与配色（全图统一）

三张 GvG 地图共用同一套四势力，**id 固定 `A` / `B` / `C` / `D` 不变，只换显示名与颜色**；与六职业配色是两套独立色板，不得互相替换。霍纳奇斯山脉只有 2 势力（`factionCount: 2`，取 A 夜枭 / B 黑皇帝）。

| id | 势力 | 颜色 | 色系 | 对 `--panel #10151d` 正文对比度 |
| --- | --- | --- | --- | --- |
| A | 夜枭 | `#F0CE45` | 黄 | 11.6:1 |
| B | 黑皇帝 | `#4A86D8` | 蓝 | 5.0:1 |
| C | 血皇帝 | `#DC5A55` | 红 | 4.9:1 |
| D | 冥皇 | `#46A86B` | 绿 | 6.2:1 |

- 四色要求：暗底上作文字 / 描边可读（正文 ≥ 4.5:1），且四色肉眼可区分。
- 血皇帝红刻意避开战后分析高风险的语义红（`#ffb3ae` 文字 / `#8e2f3c` 描边），避免同一屏内混淆。
- 势力名 / 颜色唯一来源是 `data/classes.js` 的 `defaultFactions`；地图数据、图例、守卫归属、结界、标记颜色都从这里取。

### 4.1 通用坐标系与默认视图

- 世界坐标 = 每张图自己的 `board.width × board.height`；渲染时按 `S = min(1600/bw, 1000/bh)` 等比铺满 `viewBox`，居中偏移 `ox = (1600 − bw·S)/2`、`oy = (1000 − bh·S)/2`。旧图 `1600×1000` → `S=1`、偏移 0，行为不变。
- `unit` 地图判定：显式声明 `md.unit`（猎龙之城、星墓高原）或带墙体环 `md.geometry.rings`（四方战）。
- 默认视图 `board.defaultView()`：unit 图 → `tacticalView()`（1 unit ≈ 6 屏幕 px）；普通图 → `fitView()`（k = 1）。切图与首次进入都走这套。
- 视图缩放范围 `k ∈ [0.4, 8]`。

### 4.2 猎龙之城 · `siege-capture`（`mapVersion: 3`）

- 画布 `960 × 540 unit`；`1 unit = 2 图像 px`（参考图 1920×1080 按 `unitsPerPixel = 0.5` 换算），主环道实测约 24 图像 px = 12 unit；单层 `ground`。
- 视图：`S = min(1600/960, 1000/540) = 1.6667`、`ox = 0`、`oy = 50`；默认战术缩放（1 unit ≈ 6 屏幕 px）。
- 4 势力：噬王庭北 B=黑皇帝蓝 / 冥河殿南 D=冥皇绿 / 血色宫西 C=血皇帝红 / 夜色城东 A=夜枭黄；对应北门 / 南门 / 西门 / 东门。
- 9 个热区：4 石碑（点击轮换归属）、4 城门（未解锁 / 可攻 / 已破，点击破门或撤销）、中央高台（半径 34，积分 0–100，每人每秒 0.5）。
- 城门解锁：每门绑定两座石碑（`unlocks`），两块都归同一势力 → 「可攻」；标记破门 → 「已破」。
- 石碑位置来源：四块石碑的 `x/y` **由路网几何求出，不按四角均分、不做镜像假设、不目测落点**。管线为「`roadNet` 路径 → 扫描线 even-odd 栅格化 → Zhang–Suen 细化得骨架 → 候选点外侧环带 `r = 10~26 unit` 采样路面弧段数 → 判据：弧段数 = 5、单臂宽 4°~26°、臂间最小角距 ≥ 30°、`r = 28~40 unit` 仍延续 → 四象限窗口内前三名取均值 + 0.25 unit 网格精化」。**偏移量 = 0**（点即路口中心，不额外推开）。四个路口世界坐标：西北 `(397, 180.25)`、东北 `(563.5, 173.25)`、西南 `(388, 353)`、东南 `(570.75, 347.25)`；`objectives` 与 `siege.steles` 两处同值。
- 门-碑对应（按石碑到城门的欧氏距离取最近两碑，每碑恰被 2 门引用）：**北门 = 西北 + 东北**、**南门 = 西南 + 东南**、**西门 = 西北 + 西南**、**东门 = 东北 + 东南**。石碑换位后该绑定关系未变，`siege.gates[].unlocks` 原样保留。

### 5.2 计算口径

- capture：按 1 秒步长推进，但**只有每 `bigTickSeconds`（默认 60）秒节点触发一次结算**，没有第二条结算路径。每个守卫的归属只在阶段起点变化；首次由无主 → 有主发一次 `firstCapturePoints`（开局已归属的不补发）。基础结算 = 已占领守卫数 × `bigPointsPerGuard`（18）；若该 60 秒结算点落在高倍窗口内，只有被轮转抽中的组内、且当前已归属的守卫改为 `18 × 组倍率`，组外守卫仍按 18。任一势力达到 `targetScore` 立即锁定并停止推进（曲线抽样 ≤ 300 点，模拟上限 `min(duration, 7200)`）。无人达标则按 积分 → 总击杀 → 非凡评分总和 排位取首位为胜者，同分时标记「同分按击杀 / 评分决胜」。
- escort：占领圈归属按判定圆（7 unit）人数判定；**跟随**按跟随圆（默认 20 unit）人数判定，人数最多且 ≥ 5 人的势力获得跟随，并列时保持原归属、无原归属则中立。护送速度 = `baseSpeed + perEscorterSpeed×(护送人数−1)`（护送人数取跟随圆内携带方人数）；无人护送速度 0；敌方人数多于护送方则回退。**循环护送**：首轮先按上述速度估算送达秒数，轮时长 `roundSeconds = max(escortCycleSeconds, 首轮送达秒数)`；之后每满 `roundSeconds` 秒携带方 +`deliveryPoints`（1200），骑士回中央重生，反复送达，直到 `durationSeconds`（默认 900 秒）用完。积分来源分三类并分别累计：①圈内击杀 `击杀数 × killInsideCircle`（t=0 一次性入账，可关闭）；②每 `tickSeconds` 秒给跟随圆内有人的势力加分，跟随方 +`followerPoints`、其余 +`nearPoints`；③每轮送达携带方 +`deliveryPoints`（1200）。任一势力达到 `targetScore`（15000）立即锁定并停止推进。劣势势力 = 与当前第一相差 ≥ `underdogGap`（3000）；在 `snareIntervalSeconds`（300 秒）与 `teleportIntervalSeconds`（480 秒）的节点为当时处于劣势的势力生成绊马索 / 集合传送时间轴，手动记录的秒数命中节点即标「已触发」。
- siege：`每秒速率 = 台上人数 × perMemberPerSecond`，逐步封顶 `target`，最早达标者为赢家；城门状态复用 `GM.siegeGateState(plan, gate)`。
- 结论区给出锁定胜局 / 按排位决胜、积分排位（分数 / 击杀 / 非凡评分）、高倍时间轴（时间 / 抽中组 / 覆盖守卫 / 倍率 / 额外得分 / 预告）、夺权事件、领先更替、送达首轮秒数 / 总轮次 / 累计送达分；星墓高原另给跟随判定、三类得分分列、劣势势力、绊马索 / 集合传送时间轴；结果不落盘。

### 5.3 算例

- 四方战：A 开局即占守卫 1 / 2 / 3。60 / 120 / 180 秒各结算 `3×18=54`；第 240 秒轮到 g3（守卫 3），基础 54 + 额外 `18×(4−1)×1=54` = 108，累计 270。之后 480 → g24（占守卫 2）108、720 → g15（占守卫 1）144、960 → g3 108、1200 → g24 108。
- 单局上限：5 位全占时基础 `23×5×18=2070`，5 次高倍额外共 `2×54 + 2×108 + 180 = 504`，合计约 **2574**，仍低于 3000；即按当前规则 3000 锁定在 23 分钟内打不到，见「遗留隐患」。
- 星墓高原：判定圆内 A 3 人 / B 2 人 → 占领圈归属 A；跟随圆内 A 12 人 / B 2 人 → A 获跟随（≥ 5 人）。速度 `4 + 1.33×(12−1) = 18.63 unit/秒`，到审刑广场 55.4 unit → 首轮第 3 秒送达；轮时长取 `max(60, 3) = 60` 秒。900 秒内最多 15 轮，但每 60 秒 A `+1200`、每 30 秒 A `+100` / B `+30`，A 在第 660 秒达到 `11×1200 + 22×100 = 15400`（再加 A 圈内击杀 20 人 × 5 = 100 则为 15500）≥ 15000，提前锁定；共送达 **11 轮**，累计送达分 **13200**，B 为 22×30 = 660。即默认假设值下可从「打不满」变为第 **660 秒**达标。
- 猎龙之城：台上 5 人、0.5%/秒 → 30 秒 75%；模拟 60 秒时第 40 秒达到 100% 并封顶。

### 6.2 两级导入流程

1. 编队视图 header「一键导入」→ 打开导入面板：格式要求、下载模板、拖入 / 选择文件（`.xlsx / .xlsm / .csv`）。
2. 解析成功 → 进入**预览**：成员、落位、职业来源（色 / 默 / 色?）、冲突与跳过逐条列出。
3. 预览底部选择模式并点「确认导入」才写入编成：
   - `empty` 只填空位：已占用格保持原样，冲突跳过；

4. 应用后 `roster.assertApplied` 逐块比对名字 / 职业 / 形态 / 四槽，差异必须为 0，整次导入只写一条 `GM.commit`（`Ctrl+Z` 可整次撤销）。

### 6.4 职业判定

## 七、战后分析

入口：顶栏「战后分析」→ 全屏覆盖窗口（Esc 关闭），六个页签：`1 导入` → `2 列映射` → `3 逐人分析` → `4 整体分析` → `5 疑点清单` → `阈值`；右上「导出 CSV / JSON」。

### 7.1 导入（纯前端、零依赖、只读）

- `js/xlsx.js` 自带最小 reader：扫 EOCD → 读中央目录 → 按 local header 偏移取工作表与共享字符串 → `method 8` 用 `DecompressionStream('deflate-raw')` 解压，`method 0` 直接解码。
- 支持：单表、字符串 / 数字、共享字符串、稀疏行、单元格填充色、合并信息；不处理日期格式 / 公式 / 富文本。
- 表选择：记忆表名 → 「10.17四方数据」→ 第一张；选择写 `gm.analysis.sheet.v1`。
- 降级：无 `DecompressionStream` 时红色状态条提示改用 CSV，不静默失败。CSV 支持引号包裹、`""` 转义、CRLF、BOM，表名记为 `CSV`。
- 分析结果不写回工程存档。

### 7.2 列映射（8 个字段）

`player`（必填）/ `class` / `win`（击败）/ `assist` / `damage` / `taken` / `heal` / `death`。每个字段有一组别名，导入后自动匹配并记忆到 `gm.analysis.mapping.v1`。

真实数据「10.17四方数据」实测 8 列 × 58 人：

| 列 | 表头 | 映射字段 | 填充情况 |
| --- | --- | --- | --- |
| A | 玩家名字 | `player` | 58 行全有 |
| B | 职业 | `class` | 占卜 15 / 窥秘 12 / 观众 11 / 战士 8 / 歌颂 7 / 学徒 5 |
| C | 击败 | `win` | 58 行全有 |
| D | 助攻 | `assist` | 58 行全有 |
| E | 对玩家伤害 | `damage` | 39 人有值；战士 / 观众整列空白 |
| F | 承受伤害 | `taken` | 47 人有值；观众整列空白 |
| G | 治疗 | `heal` | 仅 11 人有值（观众） |
| H | 输出承伤比 DP/TD | 不映射 | 由 E / F 计算 `damage / taken`，仅作交叉校验 |

原表没有死亡列、形态列、参战时长列，因此 `death` 不映射、死亡维度不参与；**形态只在编队里保留，不参与分析**，分组键只有职业。

### 7.3 值语义：0 与空白

| 单元格内容 | 读入结果 | 进分母 / 中位数 | 可能告警 |
| --- | --- | --- | --- |
| 数字 `0`、字符串 `"0"` / `"0.0"` | `0` | 是 | 是（0 本身可能就是疑点） |
| 空白 / 纯空格 / `—` / `-` / `N/A` | `null`（不适用） | 否 | 否（该维度直接不参与） |

`0` = 「打了，结果是 0」；`null` = 「这个职业不做这项指标」。空白不产生任何数据质量告警。

### 7.4 派生指标

| 指标 | 计算式 | 适用对象 | 空值规则 |
| --- | --- | --- | --- |
| `ka` 参与击杀 | `击败 + 助攻` | 全部 | 任一空白 → `null` |
| `ratio` DP/TD | `伤害 / 承伤` | 有伤害的人 | 承伤为 0 / 空白 → `null` |
| `outEff` 输出效率 | `伤害 / ka` | 有伤害的人 | `ka` 为 0 → `null` |
| `takenEff` 承伤效率 | `承伤 / ka` | 有承伤的人 | `ka` 为 0 → `null` |
| `takenRatio` 承伤/伤害 | `承伤 / 伤害` | 有伤害的人 | 伤害为 0 → `null`（判定时按无界） |
| `killConv` 击杀转化 | `击败 / ka` | 全部 | `ka` 为 0 → `0` |
| `healEff` 治疗效率 | `治疗 / ka` | 有治疗的人 | `ka` 为 0 → `null` |
| `median` / `Q1` / `Q3` | 同职业内非 `null` 值的中位数与线性插值四分位 | 按指标 | 分母 = 该指标非 `null` 人数 |

### 7.5 分组与分位

- 只按职业分组（占卜 / 窥秘 / 观众 / 战士 / 歌颂 / 学徒）；形态、小队、势力都不参与分组。
- 每组求 `damage / taken / heal / ka / deaths` 与派生指标的中位数、Q1/Q3；某职业整列空白时该指标中位数为 `null`、分母 0，对应维度整体跳过。
- 同职业人数 < `minGroup`（默认 3）不做判定，标「样本不足」。
- 整体分析仍输出：队伍总量、职业构成、职业分位表、异常分布、按小队聚合（需与编成匹配）、自动提示。

### 7.6 角色口径与 8 个维度

先按职业映射到三套口径，再只对本口径允许的维度打分（系数乘基准权重）：

| 口径 | 职业 | 评什么 | 明确不评 |
| --- | --- | --- | --- |
| 输出 | 歌颂 / 学徒 / 占卜 / 窥秘 | 输出占比 ×1.6、输出效率 ×1.4、承伤合理性 ×1.0、击杀转化 ×1.0、团队贡献 ×1.0、死亡偏高 ×0.7（有治疗列时治疗量 ×1.0） | 助攻参与度 |
| 治疗 | 观众 | 治疗量 ×3.0（含治疗效率）、承伤合理性 ×0.8（仅风险提示，最高「中」）、死亡偏高 ×0.6；伤害 > 0 时附加输出占比 ×0.8 / 输出效率 ×0.7 / 击杀转化 ×0.5 / 团队贡献 ×0.5，附加项不单独触发「高」 | 助攻参与度；伤害为空 / 0 时完全不评输出类 |
| 坦克 | 战士 | 承伤合理性 ×3.0（双向：过高 = 被集火，过低 = 可能没进场）、助攻参与度 ×2.5、死亡偏高 ×0.6 | 输出占比、输出效率、击杀转化、团队贡献、治疗量 |

8 个维度先算 0–1 异常度，再按口径权重求和：

| 维度 | 公式 | 异常度归一化（截断 0–1） | 默认阈值 | 基准权重 | 适用口径 |
| --- | --- | --- | --- | --- | --- |
| 输出占比 `share` | 伤害 / 同职业伤害中位 | `(shareLow − 比值) / shareLow` | `shareLow = 0.6×中位` | 0.25 | 输出；治疗（伤害 > 0 时附加） |
| 输出效率 `eff` | 伤害 / ka | `(effLow − 本人值/中位) / effLow` | `effLow = 0.7×中位` | 0.20 | 输出；治疗（附加） |
| 承伤合理性 `taken` | 承伤 / 同职业承伤中位；输出口径另看 承伤 / 伤害 | 输出：`max(承伤倍数/takenHigh − 1, 承伤伤害比倍数/takenRatioHigh − 1)`；坦克另加「过低」`(takenLow − 倍数)/takenLow` | `takenHigh = 1.4×中位`、`takenRatioHigh = 1.2×中位`、`takenLow = 0.6×中位` | 0.15 | 输出 / 治疗（仅偏高）/ 坦克（双向） |
| 击杀转化 `conv` | 击败 / ka | `(convLow − 本人转化率) / convLow` | `convLow = 0.30` | 0.15 | 输出；治疗（附加） |
| 团队贡献 `contrib` | 击败 + 助攻 与同职业 Q1 比较 | `(Q1×contribQ1 − 本人值) / (Q1×contribQ1)` | `contribQ1 = 1.0×Q1` | 0.15 | 输出；治疗（附加） |
| 治疗量 `heal` | 治疗 / 同职业治疗中位；治疗 / ka | `max(治疗倍数缺口, 治疗效率缺口)` | `healLow = 0.5×中位`、`healEffLow = 0.7×中位` | 0.10 | 治疗（主）；输出（有治疗列） |
| 死亡偏高 `death` | 死亡 / 同职业死亡中位 | `死亡倍数/deathHigh − 1` | `deathHigh = 1.5×中位` | 0.10 | 有死亡列时（三口径） |
| 助攻参与度 `assist` | 助攻 / ka | `(assistLow − 助攻占比) / assistLow` | `assistLow = 0.35` | 0.10 | 坦克 |

- 综合异常分 `composite = Σ(异常度 × 权重) / Σ权重`，分母只算本行适用且未豁免的维度。
- 分档：`≥ 0.55 → 高`；`≥ 0.32 → 中`；`≥ 0.18 → 低`；低于低档线不进清单。清单按分数降序，同分按行序；卡片只显示主因（`异常度 × 权重` 最大的适用维度），完整明细在展开区。
- 每个维度带 `applicable` / `naText`：口径不评 →「治疗口径不评这项指标」；口径允许但缺列 →「未映射死亡列 / 本场无治疗数据」等；不适用维度置灰、权重 0。

### 7.7 零值规则与反向豁免（默认开启，可逐条关闭）

| 口径 | code | 触发条件 | 分档 / 分数 |
| --- | --- | --- | --- |
| 输出 | `zero-idle` 疑似未参战 | 伤害 = 0 且 承伤 = 0 且 ka = 0 | 高 / 0.55 |
| 输出 | `zero-suppressed` 被压制 | 伤害 = 0 且 承伤 ≥ 同职业承伤中位 × `zeroTakenRatio`（默认 0.5） | 高 / 0.72 |
| 输出 | `zero-kill` 零输出但参与击杀 | 伤害 = 0 且 ka > 0（未达上面两条） | 中 / 0.42 |
| 坦克 | `tank-taken-zero` 承伤为 0 | 承伤 = 0 | 中 / 0.42 |
| 治疗 | — | 不跑零值规则 | — |

- 反向豁免（占卜类控场 / 游走）：伤害 < 中位 × `shareLow` 且 承伤 ≤ 中位 × 0.75 且 击杀转化 ≥ max(`convLow`, 同职业转化中位) → 输出占比 / 输出效率标记 exempt，从综合分剔除。
- 观众降级：治疗维度命中但 ka ≥ 同职业中位 × 1.5 → 分档降一级（高→中、中→低）。

| --- | --- | --- | --- | --- | --- |
| 宽松 `loose` | ×0.8 | ×1.2 | ×0.9 | ×1.15 | 疑点更少 |

| 严格 `strict` | ×1.2 | ×0.85 | ×1.1 | ×0.9 | 疑点更多 |

- 默认值：`minGroup 3`；`scoreLow / Mid / High = 0.18 / 0.32 / 0.55`；权重 `0.25 / 0.20 / 0.15 / 0.15 / 0.15 / 0.10 / 0.10 / 0.10`；零值规则全开、`zeroTakenRatio 0.5`、`exemptionOn` 开。
- 改动即时写 `gm.analysis.settings.v1` 并重算全部页签；分档线自动保持 `低 < 中 < 高`。

### 7.9 导出结构

### 8.2 撤销与自动保存

- 撤销栈为整份工程 JSON 快照，上限 **60 步**；`GM.commit()` 写栈 + 触发自动保存，`GM.refresh()` 只刷新视图。

- 抽屉字段编辑 400ms 防抖 commit；「确认」立即 commit 并关闭，「取消（回滚）」恢复快照并写一条撤销记录。

- 导出：`诡秘战术板_<战役名>_<日期>.json`，内容 = 工程副本 + `live`（`teams` 副本）+ `presets` + `liveNote` + `exportedAt` + `app`。

## 十、已知限制

- **没有战斗结算**：保护结界、城墙都只是视觉信息；中央高台积分靠手动输入；推演只做线性 / 步长推演。
- 推演系数、战后分析阈值与权重全是假设值，默认值不代表游戏真实规则。
- capture 模拟上限 3600 秒、escort 上限 900 秒（`durationSeconds`，可改），超出不继续外推。
- 星墓高原 15000 分按默认假设值（30 秒、跟随 +100 / 非跟随 +30、每轮 +1200、击杀 +5/人）已能在推演内达标（默认第 660 秒、11 轮送达）；但「单轮护送耗时 60 秒」与定时周期 / 分值都是假设值，真实节奏未给出，需要按实际对局改面板参数。
- xlsx 解析依赖 `DecompressionStream`；不支持日期 / 公式 / 富文本；不提供 xlsx 导出。
- 战后分析只按职业分组，形态不参与；真实表没有死亡列时死亡维度自动不生效。
- 星墓高原部分名称与几何属遮挡推断（「夜枭」「归亡」、西 / 东楼梯、合并路段），不是 100% 原图。

## 附录 · 文字可读性基线

暗色底文字按**实际合成底色**计算 WCAG 相对亮度对比度；面板底取样 `#10151d`（`--panel`），最亮叠加态 `#262d39`（悬停 / 高亮行）。

### A.1 阈值

| 用途 | 最低对比度 | 备注 |
| --- | --- | --- |
| 正文 / 主数值 / 表头 / 按钮文字 | **≥ 4.5:1** | 对 `--panel` 与最亮叠加态同时成立 |
| 次要说明 / 单位 / 计数 / 占位 | **≥ 3:1** | 不允许用 `opacity` 压暗实现层级 |
| 禁用态文字 | **≥ 2.5:1** | 必须靠明确色值 + 边框 / 底色可辨 |
| 占位虚线 / 空态边框（非文字） | **≥ 3:1** | 用 `--line-3` |
| 色块上的文字（职业色底） | **≥ 4.5:1** | 由 `textOn()` 取 `#141008` / `#f7f2e6` 高者 |

### A.2 文字色 token

### A.3 禁用写法

- ❌ `color: #555` / `#666` / `#777` / `#8a919f` 做正文（对 `--panel` 仅 2.5–5.8:1，最亮叠加约 2）。
- ❌ `opacity: .3–.6` 压暗文字。
- ❌ `color: var(--text-3, #7f8896)` 这类未定义变量 + 暗色回落。
- ❌ 用 `filter: brightness() / blur()` 表现禁用。
- ✅ 禁用态 = `color: var(--fg-disabled)` + 降低边框 / 背景明度。
- ✅ 空态虚线用 `--line-3`，文案用 `--fg-mute`。
- ✅ 职业色块文字统一走 `textOn(color)`，禁止写死白或黑。
